# Configuration

Reference for every config knob the gateway accepts, every environment
variable the embedder reads, every CLI flag, and what each script in
`scripts/` does.

## Gateway config (`gateway.toml`)

The gateway loads its config from a TOML file passed via
`--config <path>` or `MUSIC_GATEWAY_CONFIG=<path>`. The schema is
defined in `crates/music-gateway/src/config.rs`; this doc is generated
from that file.

### `[server]`

| Field | Type | Required | Description |
|---|---|---|---|
| `listen` | `SocketAddr` | yes | Address the gateway binds to. Use `0.0.0.0:8443` to accept LAN traffic; `127.0.0.1:8443` to restrict to localhost. |
| `tls_cert` | path | yes | PEM-encoded TLS certificate. Generated by `./scripts/dev-certs.sh`. |
| `tls_key` | path | yes | PEM-encoded TLS key. |
| `bearer_token` | string | yes | Static shared bearer token for the CLI (transitional — moves to OAuth Device Grant in P4). Generate with `openssl rand -hex 32`. |

### `[upstream]`

Where Navidrome lives. The gateway authenticates to Navidrome with
these creds; per-user auth is handled separately at the OAuth layer.

| Field | Type | Required | Description |
|---|---|---|---|
| `navidrome_url` | string | yes | Base URL, e.g. `http://nav.lan:4533`. Trailing slash optional. |
| `username` | string | yes | Navidrome username. |
| `password` | string | yes | Navidrome password. |

### `[cache]`

L2 metadata cache. SQLite-backed.

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `path` | path | no | `gateway-cache.sqlite` | SQLite file path. |
| `browse_ttl_seconds` | u64 | no | `86400` (24 h) | TTL applied to cached browse-endpoint responses. |

The cache is throwaway — deleting the file at any time is safe. ETags
get re-derived on the next refresh.

### `[oauth]`

OAuth 2.1 server state. Lives in its own SQLite file (separate from
the metadata cache because this DB holds irreplaceable refresh
tokens).

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `state_db` | path | no | `gateway-state.sqlite` | SQLite file holding users, clients, codes, tokens, sessions. |
| `clients` | array of tables | no | `[]` | Pre-declared OAuth clients, registered at startup. |

### `[[oauth.clients]]`

Pre-declared clients. Listed inline in `gateway.toml` so the client
registry is Git-trackable instead of needing an admin endpoint.
Registration is idempotent at startup — already-registered
`client_id`s are skipped.

| Field | Type | Required | Description |
|---|---|---|---|
| `client_id` | string | yes | Stable client identifier. The web app expects `"web"`. |
| `name` | string | yes | Display name shown on the consent screen. |
| `redirect_uris` | array of string | yes | Allowed redirect URIs. Strict equality, no wildcards. |

Example:

```toml
[[oauth.clients]]
client_id     = "web"
name          = "Web"
redirect_uris = [
    "http://localhost:5173/oauth/callback",      # Vite dev
    "https://gateway.local:8443/oauth/callback", # production same-origin
]
```

### `[embedder]` (optional)

Python sidecar for CLAP audio + text embeddings. If absent, the
gateway runs in degraded mode and recommend endpoints fall back to
tag-only similarity.

If present but unreachable at boot, same outcome — a warning is
logged and the gateway proceeds without embedder support.

| Field | Type | Required | Default | Description |
|---|---|---|---|---|
| `url` | string | yes | — | Sidecar base URL, e.g. `http://localhost:9000`. |
| `timeout_seconds` | u64 | no | `30` | Per-request timeout. CPU-only CLAP inference on a 120 s clip can take 10+ s, so don't go too aggressive. |

## CLI config (`~/.config/crates-music/config.toml`)

The `music` CLI looks up its config via [`directories`](https://crates.io/crates/directories):

- Linux: `~/.config/crates-music/config.toml` (or `$XDG_CONFIG_HOME`)
- macOS: `~/Library/Application Support/crates-music/config.toml`
- Windows: `%APPDATA%\crates-music\config.toml`

```toml
[server]
url      = "http://nav.lan:4533"
username = "alice"
password = "wonderland"

[gateway]
url          = "https://gateway.local:8443"
bearer_token = "<same token as gateway.toml>"
```

`[server]` is kept so you can flip to direct-to-Navidrome mode (no
gateway) for diagnostics. `[gateway]` takes precedence when present.

Cache directory follows the same XDG layout under
`$XDG_CACHE_HOME/crates-music/`.

## Environment variables

### Gateway

| Variable | Default | Description |
|---|---|---|
| `MUSIC_GATEWAY_CONFIG` | — | Path to `gateway.toml`. Overridden by `--config` flag. |
| `RUST_LOG` | `info` | Tracing filter. `RUST_LOG=music_gateway=debug,sqlx=warn` is a good debug starting point. |

### Embedder

| Variable | Default | Description |
|---|---|---|
| `EMBEDDER_BACKEND` | `stub` | `stub` for deterministic hash vectors (no GPU); `clap` for the real LAION CLAP backend. Any other value → service refuses to start. |
| `CLAP_CHECKPOINT` | — | Required when `EMBEDDER_BACKEND=clap`. Path to a `.pt` checkpoint file. |
| `HIP_VISIBLE_DEVICES` | — | AMD ROCm: pin to a specific GPU index (e.g. `0`). Recommended on hosts with both a discrete and integrated GPU — without pinning, torch may pick the iGPU. |
| `CUDA_VISIBLE_DEVICES` | — | NVIDIA equivalent of `HIP_VISIBLE_DEVICES`. |
| `HSA_OVERRIDE_GFX_VERSION` | — | AMD ROCm fallback: e.g. `11.0.0` to make a newer card identify as RDNA3. Only needed when the installed ROCm version pre-dates native support for the card. |

The embedding dimension is fixed at 512 (constant `EMBEDDING_DIM` in
`embedder/app.py`); both the CLAP audio + text encoders and the stub
backend produce 512-dim vectors.

Device selection for the CLAP backend is whatever
`laion_clap.CLAP_Module` picks up at load time. The current device is
reported on `/healthz` as `device: "cpu" | "cuda"`; the gateway boot
log echoes it as `embedder: ready ... device="cuda"`. ROCm-built
torch reports HIP devices as `"cuda"`, so `device="cuda"` with an AMD
card means GPU is engaged.

For ROCm install + torch wheel pinning, see
[`docs/components/embedder.md`](./components/embedder.md#gpu-acceleration-amd-rocm).

### Web

The Vite dev server reads from `apps/web/vite.config.ts`, not env
vars. Production builds are served by the gateway and don't need
configuration — they hit the same origin they were served from.

### CLI

| Variable | Description |
|---|---|
| `RUST_LOG` | Tracing filter. Same syntax as the gateway. |
| `XDG_CONFIG_HOME` | Override config search root (Linux). |
| `XDG_CACHE_HOME` | Override cache search root (Linux). |

## Scripts

### `scripts/dev-certs.sh`

Generates local TLS certs via `mkcert`. Idempotent. On first run it
also installs the local CA into your system trust store (may prompt
for sudo). Output:

- `certs/gateway.local.pem`
- `certs/gateway.local-key.pem`

The default `gateway.toml` references these paths relative to the
repo root.

If you want certs for a different hostname, edit the script — the
hostname is hardcoded so the cert SAN is predictable.

## Cargo workspace

| Command | What it does |
|---|---|
| `cargo build --workspace` | Build all crates in dev profile. |
| `cargo build --release -p music-gateway` | Optimised gateway binary at `target/release/music-gateway`. |
| `cargo test --workspace` | Run all tests. |
| `cargo test -p music-gateway --test recommend` | Run the `tests/recommend.rs` integration suite for the gateway. |
| `cargo test -p music-recommend events::` | Run unit tests with `events::` in the path. |
| `cargo clippy --workspace --all-targets -- -D warnings` | Lint. CI-equivalent. |
| `cargo fmt --all` | Format. |
| `cargo run -p music-cli -- <args>` | Run the CLI. |
| `cargo run -p music-gateway -- --config gateway.toml` | Run the gateway. |

The workspace lints (in the root `Cargo.toml`):

- `unsafe_code = "forbid"` — no unsafe anywhere.
- `unreachable_pub = "warn"` — flags pub items that aren't actually exported.
- `missing_debug_implementations = "warn"` — every type should be `Debug`.
- `clippy::pedantic` at warn level. A handful of pedantic lints are
  individually disabled (see the workspace Cargo.toml) when they
  fight legitimate proper nouns or conflict with the project's style.

## npm (web app)

Run from `apps/web/`:

| Command | What it does |
|---|---|
| `npm install` | Install dependencies. |
| `npm run dev` | Vite dev server on http://localhost:5173. |
| `npm run build` | Type-check (`tsc -b`) and build to `dist/`. |
| `npm run lint` | Type-check only (no emit). |
| `npm run preview` | Serve the production build locally. |

## Python (embedder)

Run from `services/embedder/`. Recommended: `uv` (faster than pip).

| Command | What it does |
|---|---|
| `uv sync` | Install deps into a local `.venv` (stub backend only). |
| `uv sync --extra clap` | Add CLAP + PyTorch + librosa for the production backend. |
| `uv sync --extra dev` | Add pytest + httpx for the test suite. |
| `uv run uvicorn embedder.app:app --port 9000` | Start the sidecar. |
| `uv run pytest` | Run the test suite. |
