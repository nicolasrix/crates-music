# Deployment

This doc covers running the gateway + embedder stack in containers.
Navidrome is **not** part of the stack — point the gateway at an
existing Navidrome instance (anywhere reachable on the network).

The dev path (cargo + Vite + uv) lives in
[`GETTING-STARTED.md`](./GETTING-STARTED.md); use this doc when you're
deploying for real.

## What ships

Two containers:

| Container | Image tag (local) | Process | Ports | Volumes |
|---|---|---|---|---|
| Gateway | `crates-music/gateway:dev` | Rust binary + React SPA | `8443` (host) | `gw-data` → `/data` |
| Embedder | `crates-music/embedder:dev` | Python FastAPI (stub backend in Phase A) | `9000` (internal-only) | `gw-data` → `/data` (shared with gateway, see below) |

The gateway image bakes in the built SPA at `/etc/gateway/web/dist`
and serves it as a same-origin static site, so there's no separate
web container.

**Shared volume.** Both containers mount the same `gw-data` named
volume at `/data`. The gateway is the primary writer (OAuth state,
embeddings, caches, certs); the embedder writes only the UMAP
projection rows back into `gateway-state.recommend.sqlite` when the
gateway's auto-projection task asks it to. Both containers therefore
run as the same numeric uid (`10001`) so file ownership matches across
the boundary — pin Dockerfile changes to that uid, or the cross-write
breaks silently.

## First-boot sequence

```bash
# 1. Make sure Navidrome is reachable on the LAN.
curl -s http://nav.lan:4533/rest/ping?u=…&p=…&v=1.16.1&c=test&f=json

# 2. Copy the env template and fill in the three required values.
cp docker/.env.example .env
$EDITOR .env   # NAVIDROME_URL, NAVIDROME_USERNAME, NAVIDROME_PASSWORD

# 3. Build and bring up the stack.
docker compose up --build

# 4. The gateway logs a one-time setup token URL on first boot:
#       "gateway is unconfigured — visit https://0.0.0.0:8443/oauth/setup with token: …"
#    Open the URL in a browser (accept the self-signed cert warning),
#    set a master password, then sign in to the web app at the same
#    origin.
```

On second and later boots the gateway reuses the bearer token, TLS
cert, and OAuth state from the `gw-data` volume — nothing changes
unless you delete the volume.

## Environment reference

Everything is read from env vars at container start and templated into
`/data/config/gateway.toml`. Source of truth: `docker/gateway/gen_config.py`.

### Required

| Variable | Description |
|---|---|
| `NAVIDROME_URL` | e.g. `http://nav.lan:4533`. No trailing slash needed. |
| `NAVIDROME_USERNAME` | Navidrome admin account the gateway authenticates with. |
| `NAVIDROME_PASSWORD` | Plain-text Navidrome password. |

### Optional

| Variable | Default | Description |
|---|---|---|
| `GATEWAY_PORT` | `8443` | Host port to bind. Container always listens on 8443 internally. |
| `GATEWAY_HOSTNAME` | `gateway.local` | Hostname the auto-generated self-signed cert is issued for. |
| `GATEWAY_BEARER_TOKEN` | autogenerated | Legacy bearer used by the CLI. Persisted to `/data/state/bearer.token` on first boot if unset. |
| `OAUTH_WEB_REDIRECT_URIS` | `https://gateway.local:8443/oauth/callback` | Comma-separated list. Strict equality, no wildcards. |
| `EMBEDDER_URL` | `http://embedder:9000` (set by compose) | Sidecar base URL. Leave unset to run in degraded mode (no recommendations). |
| `EMBEDDER_TIMEOUT_SECONDS` | `30` | Per-request timeout. CPU-only CLAP / CLaMP 3 can hit 10+ s. |
| `GATEWAY_TLS_CERT` | `/data/certs/gateway.local.pem` | Override to mount your own cert. |
| `GATEWAY_TLS_KEY` | `/data/certs/gateway.local-key.pem` | — |
| `GATEWAY_STATE_DB` | `/data/state/gateway-state.sqlite` | Override only if you split state across filesystems. |
| `GATEWAY_CACHE_DB` | `/data/state/gateway-cache.sqlite` | — |
| `GATEWAY_BROWSE_TTL_SECONDS` | `86400` | L2 metadata cache TTL. |
| `WEB_STATIC_DIR` | `/etc/gateway/web/dist` (set in the image) | Where the gateway serves the SPA from. Empty string disables static serving. |
| `RUST_LOG` | `info,music_gateway=info,sqlx=warn` | Tracing filter. |
| `EMBEDDER_BACKEND` | `stub` | `stub` (deterministic hash vectors), `clap` (LAION CLAP, 512-dim), or `clamp3` (CLaMP 3, 768-dim — the production backend). Set on the **embedder** container. |
| `RECOMMEND_EMBEDDING_DIM` | unset → `512` | Gateway-side embedding dimension. When set, `gen_config.py` emits a `[recommend]\nembedding_dim = …` section into the generated `gateway.toml`; when unset there is no `[recommend]` section and the gateway defaults to **512** (CLAP). Set to `768` for CLaMP 3. Must match the embedder's actual dim. ⚠️ See the silent-no-op caveat below. |
| `CLAMP3_CHECKPOINT` | — | (CLaMP 3 only) Path inside the embedder container to the unified saas CLaMP 3 checkpoint (`.pth`). |
| `MERT_FOLDER` | — | (CLaMP 3 only) Local copy of the `m-a-p/MERT-v1-95M` frontend (or a hub id when the embedder can reach the HF hub). |
| `CRATES_CONFIG_DIR` | — | (CLaMP 3 compose overlays only) Host directory the containers bind-mount component data from; the embedder reads the saas checkpoint from its `models/` subdirectory. Required by `docker-compose.clamp3.yml` / `.clamp3-rocm.yml`. |
| `RECOMMEND_LEASH_TAU` | unset → `0.28` | Anchor-leash cosine threshold for travelling autoplay stations. Server fallback; web Settings sends per-request overrides. |
| `RECOMMEND_LEASH_LAMBDA` | unset → `16` | Anchor-leash demotion strength `λ·(τ − sim)²`. `0` disables the leash. |
| `RECOMMEND_LOG_PROVENANCE` | unset → `true` | Persist every served recommendation slate + scores to `gateway-state.recommend.sqlite` (append-only training data). `false` stops capture. |

**`RECOMMEND_EMBEDDING_DIM` silent-no-op caveat.** The variable is only
read by `gen_config.py`, which is **baked into the gateway image**. A
YAML-only `RECOMMEND_EMBEDDING_DIM` edit against a gateway image built
*before* 768 support is a silent no-op — the old `gen_config.py` simply
ignores the variable and emits no `[recommend]` section, so the gateway
keeps defaulting to 512. Flipping the dim therefore requires a gateway
image that contains the updated `gen_config.py`, not just an env change.
See the ANN-wipe requirement in [Running with CLaMP 3](#running-with-clamp-3-768-dim-production).

The web client (Phase B follow-up) and operator-mounted certs can ride
on the same env surface — see the `[server]`/`[oauth]` blocks in
[`CONFIGURATION.md`](./CONFIGURATION.md) for the underlying TOML schema.

## Resource limits & log rotation

The compose files cap each container's memory and rotate its JSON log
file by default. The intent is "an OOM in one container can't take the
host down, and `docker logs` can't fill the disk." Defaults:

| Service | Default `mem_limit` | Notes |
|---|---|---|
| `gateway` | `1g` | Mostly I/O bound. Bump if you raise the audio cache budget into the multi-GB range. |
| `embedder` (stub) | `512m` | Tiny — numpy + a couple of buffers. |
| `embedder` (CLAP CPU, `.clap.yml`) | `4g` | ~2 GB of float32 weights + librosa/torch working memory. |
| `embedder` (CLAP ROCm, `.clap-rocm.yml`) | `6g` | Model lives on the GPU; CPU mirror + MIOpen JIT pipeline costs ~5 GB sustained. |
| `embedder` (CLaMP 3 CPU, `.clamp3.yml`) | `6g` | Holds MERT-v1-95M + xlm-roberta-base + the saas CLaMP 3 checkpoint in RAM — several GB resident. |
| `embedder` (CLaMP 3 ROCm, `.clamp3-rocm.yml`) | `8g` | Same three models, plus the ROCm runtime + MIOpen JIT pipeline. Split-host GPU shape. |
| `navidrome-stub` (smoke profile) | `128m` | One-file Python server. |

All capped via env in `.env`:

```
GATEWAY_MEM_LIMIT=2g
EMBEDDER_MEM_LIMIT=8g     # honoured by base + all CLAP/CLaMP 3 overrides
```

JSON log rotation is global:

```
LOG_MAX_SIZE=10m          # per file
LOG_MAX_FILE=3            # rotated files retained
```

Logs are still streamed live via `docker compose logs -f`; rotation
only governs the on-disk JSON tail.

If a container hits its memory cap, Docker OOM-kills it and `restart:
unless-stopped` brings it back. Check with `docker inspect <id> --format
'{{.State.OOMKilled}}'` after a crash — if `true`, raise the cap.

## Volumes

One named volume, `gw-data`, mounted at `/data` in the gateway container.
Layout under `/data`:

```
/data/
├── config/            # generated gateway.toml (inspect when debugging)
├── certs/             # gateway.local.pem + key (self-signed on first boot)
├── state/
│   ├── gateway-state.sqlite              # OAuth: users, clients, tokens
│   ├── gateway-state.recommend.sqlite    # embeddings, ingest queue, events
│   ├── gateway-state.traces.sqlite       # diagnostics ring
│   ├── gateway-state.ann                 # HNSW mmap
│   ├── gateway-state.ann.keys            # ANN ↔ track-id sidecar
│   ├── gateway-cache.sqlite              # L2 metadata cache (disposable)
│   └── bearer.token                      # autogenerated, mode 0600
└── audio/             # L4 transcoded-stream cache (when implemented)
```

The embedder is stateless in Phase A and doesn't mount any volumes.

### uid alignment

Both containers run as the same numeric uid (`10001`) and gid (`10001`)
so the embedder can write into `gateway-state.recommend.sqlite` after
the gateway opened it. If you're carrying a `gw-data` volume from a
build that predates this pin, the files inside are owned by whatever
uid `useradd --system` happened to allocate at image-build time
(typically `999`). Rebuild against the new images and either:

- start fresh (`docker compose down -v`, lose the volume — fine on a
  first-deploy machine), or
- one-shot chown the volume contents to `10001:10001`:

```bash
docker run --rm -v cratesmusic_gw-data:/data alpine \
    chown -R 10001:10001 /data
```

### What to back up

**Critical, can't be re-derived from anywhere:**

- `state/gateway-state.sqlite` — OAuth refresh tokens, users, clients. Lose
  this and every paired device has to re-pair.
- `state/gateway-state.recommend.sqlite` — embeddings + event log. Lose this
  and you re-compute every track embedding from scratch (slow with CLAP /
  CLaMP 3).
- `state/bearer.token` — legacy CLI auth. Cheap to regenerate but every CLI
  has to be reconfigured.
- `certs/` — only if you've replaced the self-signed cert with one you
  paid for.

**Don't bother backing up** (rebuild on demand):

- `gateway-cache.sqlite` — L2 metadata cache. Re-fetches from Navidrome.
- `gateway-state.ann` / `.ann.keys` — derived from `recommend.sqlite`,
  rebuilt at boot. ⚠️ **Must be wiped when the embedding dim changes
  (512↔768)** — see the dim-change warning below.
- `gateway-state.traces.sqlite` — diagnostics ring, write-only-recent.
- `audio/` — transcoded-stream cache. Regrows from Navidrome.

> ⚠️ **ANN wipe on embedding-dim change (512↔768).** Changing the
> embedding dim is **not migratable**. `AnnIndex::open()` blindly loads
> whatever `.ann` is on disk with no dim-mismatch guard, so a 768
> gateway booting on a stale 512 `.ann` ends up split-brained and
> corrupts. Before the **first boot on a new dim** you must delete
> `gateway-state.ann` **and** `gateway-state.ann.keys` from
> `/data/state/`, then restart — the gateway boots clean (empty index)
> and rebuilds it from `gateway-state.recommend.sqlite`. The ANN is a
> derived cache; SQLite is authoritative, so the embedding rows survive
> the wipe (no re-embedding needed for the dim already in SQLite — but a
> CLAP→CLaMP 3 swap *does* mean re-embedding, since the 512 vectors are
> useless to a 768 index).

## Health endpoints

Two endpoints, intentionally distinct:

| Endpoint | Purpose | Status |
|---|---|---|
| `GET /healthz` | **Liveness.** Process is up and the axum runtime is serving. Always 200. Use this when you want "should I restart the container?" semantics. | 200 always |
| `GET /readyz` | **Readiness.** Probes upstream Navidrome (Subsonic `ping`, 2 s timeout) and the configured embedder. Use this when you want "can this container actually serve traffic right now?". | 200 ready, 503 degraded |

The container `HEALTHCHECK` is pointed at `/readyz`, so a Navidrome
outage (or a configured-but-unreachable embedder) flips the gateway
container to `unhealthy` within one healthcheck interval (~30 s). This
is what makes `depends_on: service_healthy` meaningful for any future
service we layer in front (e.g. a reverse proxy).

`/readyz` response shape (degraded example):

```json
{
  "status": "degraded",
  "service": "music-gateway",
  "checks": {
    "navidrome": { "status": "error", "error": "..." },
    "embedder":  { "status": "ok", "dim": 768 }
  }
}
```

Embedder check semantics:

- No `[embedder]` block → `"status": "disabled"` (not a failure).
- Configured & last probe saw the model loaded → `"status": "ok"`.
- Configured & last probe was unreachable / loading → `"status": "error"` and overall 503.

## TLS

The entrypoint mints a self-signed cert for `$GATEWAY_HOSTNAME` (default
`gateway.local`) on first boot if `/data/certs/` is empty. Pros: no
external dependencies, the gateway starts on first launch with no
manual steps. Cons: every client has to accept a security warning the
first time it connects.

**Production paths:**

1. **Mount your own cert.** Drop PEM-encoded `gateway.local.pem` and
   `gateway.local-key.pem` into the `certs/` subdirectory of the
   `gw-data` volume before first boot. The entrypoint detects existing
   files and skips the self-sign step.
2. **Reverse proxy with public TLS.** Put Caddy or Traefik in front
   of the gateway. The internal gateway can still use a self-signed
   cert (the proxy terminates real TLS). You'll want to point
   `OAUTH_WEB_REDIRECT_URIS` at the public URL. The bundled
   `docker/caddy/Caddyfile` (used by `docker-compose.prod.yml`) already
   sets the browser security headers: a Content-Security-Policy tuned to
   the SPA, `X-Frame-Options: DENY` + `frame-ancestors 'none'`
   (clickjacking), HSTS (`max-age=1y`), `X-Content-Type-Options`, and
   `Referrer-Policy`. If you front the gateway with your own proxy
   instead, replicate those headers.

mDNS / `/etc/hosts` on each client device is the path for option 1
(`gateway.local` → the gateway IP). Mobile devices on Android can
install the cert as a user CA from Settings → Security.

## Updates

```bash
git pull
docker compose build
docker compose up -d
```

The named volume persists across image rebuilds, so OAuth state,
bearer tokens, certs, and embeddings all carry over. The container
restarts in a few seconds — the rebuild is the long part (Rust
release build of the workspace).

Run a backup before any non-trivial upgrade — see [Backups](#backups).

## Backups

Two scripts under `scripts/` snapshot and restore the gateway's
irreplaceable state:

| Script | Purpose |
|---|---|
| `scripts/backup.sh <state-dir> <output-dir>` | Online snapshot to a timestamped `.tar.gz`. Safe while the gateway is running. |
| `scripts/restore.sh [--force] <archive> <dest-dir>` | Verify checksums and restore. Refuses to clobber a non-empty dest without `--force`. |

**What's in a backup:**

- `gateway-state.sqlite` — OAuth tokens, master password, sync state, play counts.
- `gateway-state.recommend.sqlite` — CLAP / CLaMP 3 embeddings + ingest queue (skipped if absent).
- `certs/cert.pem` + `certs/key.pem` — TLS keypair (losing it means re-trusting on every paired device).
- `manifest.json` — sha256 of each file. Restore aborts if any checksum doesn't match.

**Deliberately not backed up — all regenerable:**

- `gateway-cache.sqlite` (L2 metadata cache — refetches from Navidrome).
- `gateway-state.traces.sqlite` (diagnostics ring — regenerates organically).
- `gateway-state.ann` + `.ann.keys` (HNSW mmap — rebuilds at boot from `.recommend.sqlite`). ⚠️ Must be **wiped** (not just skipped) when the embedding dim changes — see [the dim-change warning](#what-to-back-up).

### Running a backup

The compose stack mounts the gateway state at `/data` inside the container
and the `gw-data` named volume on the host. The scripts run on the host
against the volume's mount point — they don't need a running gateway,
just access to the files.

```bash
# Find where docker put the volume on the host.
STATE="$(docker volume inspect crates-music_gw-data --format '{{.Mountpoint}}')"

mkdir -p /var/backups/crates-music
scripts/backup.sh "$STATE" /var/backups/crates-music
```

Output:

```
snapshotting gateway-state.sqlite...
snapshotting gateway-state.recommend.sqlite...
copying certs...
writing manifest...
writing /var/backups/crates-music/crates-music-backup-20260518T090000Z.tar.gz...
done: /var/backups/crates-music/crates-music-backup-20260518T090000Z.tar.gz (12M)
```

The archive is chmod 0600 — it contains the TLS private key and OAuth
refresh tokens. Anyone who can read it owns the deployment.

### Restoring

```bash
# Stop the gateway first — restoring over open DBs corrupts both.
docker compose stop gateway

# Wipe the volume's data and restore into it.
STATE="$(docker volume inspect crates-music_gw-data --format '{{.Mountpoint}}')"
sudo rm -rf "$STATE"/*
sudo scripts/restore.sh /var/backups/crates-music/crates-music-backup-20260518T090000Z.tar.gz "$STATE"

docker compose start gateway
```

Restore verifies every file's sha256 against `manifest.json` before
placing it. A corrupted archive fails before any state on disk is
touched.

### Cron snippet (daily, keep last 14)

```cron
# m h dom mon dow command
0 4 * * * STATE=$(docker volume inspect crates-music_gw-data --format '{{.Mountpoint}}') && /opt/crates-music/scripts/backup.sh "$STATE" /var/backups/crates-music >> /var/log/crates-music-backup.log 2>&1
5 4 * * * find /var/backups/crates-music -name 'crates-music-backup-*.tar.gz' -mtime +14 -delete
```

The two lines are separated by a minute so the deletion runs after
the new backup lands — that way a backup failure leaves you with the
old set rather than nothing.

### Restore drill

Untested backups aren't backups. The roundtrip test under
`scripts/tests/backup-roundtrip.sh` exercises the round trip against
synthetic fixtures and runs in under a second:

```bash
bash scripts/tests/backup-roundtrip.sh
# all checks passed
```

For a real-data drill: take a backup, restore it into a *separate*
state directory, point a second gateway instance at it (different
host port), and confirm OAuth login + playback work. That's the only
way to know your backup is actually viable; the in-tree test only
proves the *mechanism* is sound, not that the data on disk today is.

## Debugging

Show recent logs:

```bash
docker compose logs --tail=100 gateway
docker compose logs --tail=100 embedder
```

Inspect the generated config (handy when "the gateway is reading the
wrong Navidrome URL" suspicions arise):

```bash
docker compose exec gateway cat /data/config/gateway.toml
```

Read the autogenerated bearer token (CLI uses this):

```bash
docker compose exec gateway cat /data/state/bearer.token
```

Probe the embedder from inside the gateway container:

```bash
docker compose exec gateway curl -s http://embedder:9000/healthz
```

Drop into a shell:

```bash
docker compose exec gateway bash    # gateway runs as the `gateway` user
docker compose exec embedder bash   # embedder runs as the `embedder` user
```

## Running with CLAP (real embeddings)

The default `embedder` service runs the **stub backend** — deterministic
SHA-256-seeded hash vectors. Good enough for OAuth / sync / proxy smoke
tests, but recommendations from stub embeddings have no acoustic
meaning. For useful recommendations, swap to the CLAP variant.

Phase B step 1 ships a **CPU-only** CLAP image. Same Python sidecar,
real LAION CLAP inference, no GPU passthrough required. Slower than
the future ROCm variant (~30–90 s checkpoint load on boot, ~1 s per
embed on a modern x86-64 core), but hermetic and reproducible.

```bash
# 1. Drop a CLAP checkpoint somewhere on the host. The codebase has
#    been smoke-tested against LAION's music-audioset weights
#    (`music_audioset_epoch_15_esc_90.14.pt`, ~2.2 GB). Other LAION
#    CLAP checkpoints work; non-LAION ones do not.
ls ./models/music_audioset_epoch_15_esc_90.14.pt

# 2. Point CLAP_CHECKPOINT_PATH at it in .env.
echo 'CLAP_CHECKPOINT_PATH=./models/music_audioset_epoch_15_esc_90.14.pt' >> .env

# 3. Bring the stack up with the CLAP override file. The base
#    docker-compose.yml stays the source of truth; the override only
#    replaces the `embedder` service's image + env + volume.
docker compose -f docker-compose.yml -f docker-compose.clap.yml up --build
```

What changes vs. the stub deploy:

| | Stub (default) | CLAP CPU |
|---|---|---|
| Image | `crates-music/embedder:dev` (~350 MB) | `crates-music/embedder-clap:dev` (~3 GB) |
| First-boot time to healthy | ~5 s | 30–120 s (checkpoint load) |
| `/healthz` `device` field | `cpu` | `cpu` (CUDA-disabled torch) |
| `model_version` | `stub-v1` | derived from checkpoint filename |
| Per-embed latency | ~0.5 ms | ~700–1500 ms |

The checkpoint is bind-mounted **read-only** at `/models/clap.pt` inside
the container. We deliberately don't bake it into the image —
checkpoints are large (2+ GB) and LAION's weights ship under a
research-use license that's awkward to redistribute in a Docker tag.

The embedder healthcheck `start_period` is `120s` in the CLAP image
(vs `10s` for the stub) — that's what makes `depends_on:
service_healthy` on the gateway work without races during a cold
boot.

## Running with CLAP on AMD ROCm GPU

Phase B step 2: same CLAP backend, PyTorch built against ROCm 6.4
instead of CPU wheels. ~6× faster than the CPU variant on an RDNA4 GPU
(per-embed latency drops from ~1 s to ~150 ms). Requires an AMD GPU
that ROCm 6.4 supports — gfx1100 (RDNA3) and gfx1201 (RDNA4) are
covered by the bundled wheel runtime.

```bash
# 1. Same checkpoint as the CPU variant.
echo 'CLAP_CHECKPOINT_PATH=./models/music_audioset_epoch_15_esc_90.14.pt' >> .env

# 2. Tell compose your host's render/video group IDs. Check with:
#       getent group render video
#    Defaults in the compose file are Arch/Cachy (render=988, video=984).
#    Debian/Ubuntu typically use render=109, video=44.
echo 'RENDER_GID=988' >> .env
echo 'VIDEO_GID=984' >> .env

# 3. Bring the stack up with the ROCm override.
docker compose -f docker-compose.yml -f docker-compose.clap-rocm.yml up --build
```

Differences from the CPU variant:

| | CLAP CPU | CLAP ROCm |
|---|---|---|
| Base wheel index | `whl/cpu` | `whl/rocm6.4` |
| Image size | ~4 GB | **~23 GB** (rocm6.4 torch wheel unpacks the entire ROCm runtime) |
| Device passthrough | none | `/dev/kfd` + `/dev/dri` |
| Group membership | none | `render`, `video` (host GIDs) |
| `/healthz` `device` field | `cpu` | `cuda` (torch reports AMD GPUs as "cuda") |
| First audio embed (cold MIOpen cache) | n/a | ~2.5 s |
| Subsequent audio embed (1 s clip) | ~113 ms | ~36 ms |
| Text embed | ~170 ms | ~50 ms |
| Healthcheck `start_period` | 120 s | 60 s |

**MIOpen cold-cache penalty.** The first audio embed after any
container restart compiles GPU conv kernels into
`/var/cache/miopen/` inside the container. That's ~2.5 s of one-off
latency on the first inference of each container lifetime; everything
afterwards is fast. The cache lives in the container's writable
layer and is discarded by `docker compose down` — restarts always
eat the cold-cache cost once. If that matters for ythis deployment,
mount a named volume at `/var/cache/miopen` to persist it.

**Verifying GPU is actually being used.** After the container is
healthy, hit `/healthz` on the embedder directly and look for
`"device": "cuda"`. If it reports `"cpu"`, either the device
passthrough didn't land, the user wasn't in the right groups, or
the wheel's ROCm runtime doesn't have kernels for your card — in
that order of likelihood. Logs from `docker compose logs embedder`
will say `CLAP loaded on device=cpu` in the silent-fallback case.

**`HSA_OVERRIDE_GFX_VERSION`.** Not set by default. The rocm6.4
wheels cover gfx1100 and gfx1201 natively, so an unconditional
override would *mis*-route kernels on the cards that need them
least. Set it only as a workaround when `rocm-smi` sees your card
but torch reports `cuda.is_available()` as false inside the
container — see the commented entry in `docker-compose.clap-rocm.yml`.

A **GPU variant for NVIDIA** is not in scope — the codebase has
been developed and tested on AMD; CUDA-flavoured CLAP would mean a
third Dockerfile and a different wheel index, and there's no
hardware to validate it against.

## Running with CLaMP 3 (768-dim, production)

CLaMP 3 is the **current production content embedder** — 768-dim
vectors with stronger music-specific acoustic similarity than the
512-dim LAION CLAP backend, plus a joint text encoder that drives
natural-language stations (`GET /v1/recommend/station?text=…`). CLAP
remains a supported alternative (see the two CLAP sections above); the
two are mutually exclusive per deployment because the embedding dim
differs.

The pipeline is MERT-v1-95M frontend → CLaMP 3 audio encoder → 768-dim
L2-normed vector. Three models are resident in RAM at once (MERT-v1-95M,
xlm-roberta-base for the text tokenizer/encoder, and the unified saas
CLaMP 3 checkpoint), so the container's working set is several GB — size
the memory cap accordingly (see [Resource limits](#resource-limits--log-rotation)).

Two compose overlays, mirroring the CLAP pair:

| File | Wheel index | Device |
|---|---|---|
| `docker-compose.clamp3.yml` | CPU | none — hermetic, reproducible, slow |
| `docker-compose.clamp3-rocm.yml` | `whl/rocm6.4` | AMD GPU (`/dev/kfd` + `/dev/dri`) — the live shape |

They build from `docker/embedder/Dockerfile.clamp3` (CPU) and
`docker/embedder/Dockerfile.clamp3-rocm` (GPU) respectively. Both bake
MERT-v1-95M + xlm-roberta-base into the image's HF cache so the runtime
can stay `TRANSFORMERS_OFFLINE=1`.

```bash
# 1. Drop the unified saas CLaMP 3 checkpoint on the host and point
#    CLAMP3_CHECKPOINT at it (path is inside the embedder container).
#    ⚠️ KEEP THE UPSTREAM FILENAME — the checkpoint filename IS the
#    embedding model_version. Renaming it (e.g. to clamp3_saas.pth)
#    silently split-brains the embedding store against existing rows.
echo 'CLAMP3_CHECKPOINT=/models/weights_clamp3_saas_h_size_768_t_model_FacebookAI_xlm-roberta-base_t_length_128_a_size_768_a_layers_12_a_length_128_s_size_768_s_layers_12_p_size_64_p_length_512.pth' >> .env

# 2. Point MERT_FOLDER at a local m-a-p/MERT-v1-95M copy (or a hub id
#    if the embedder can reach the HF hub at build time).
echo 'MERT_FOLDER=/models/MERT-v1-95M' >> .env

# 3. Flip the gateway to 768 — this is what makes gen_config.py emit
#    the [recommend] embedding_dim section (see the env reference).
echo 'RECOMMEND_EMBEDDING_DIM=768' >> .env

# 4. The embedder backend selector.
echo 'EMBEDDER_BACKEND=clamp3' >> .env

# 5. Bring the stack up with the CLaMP 3 ROCm overlay (or .clamp3.yml
#    for CPU).
docker compose -f docker-compose.yml -f docker-compose.clamp3-rocm.yml up --build
```

`/healthz` on the CLaMP 3 embedder reports `"dim": 768` and, on ROCm,
`"device": "cuda"` (torch reports AMD GPUs as "cuda" — HIP shows as
cuda). The `model_version` string is long, e.g.
`weights_clamp3_saas_h_size_768_…`.

### One-time ANN wipe when switching to CLaMP 3 (REQUIRED)

Switching from CLAP (512) to CLaMP 3 (768) changes the embedding dim,
which is **not migratable**. Before the first boot on 768 you **must**:

1. Confirm the gateway image actually contains the 768-aware
   `gen_config.py` (a YAML-only `RECOMMEND_EMBEDDING_DIM=768` against an
   older image is a silent no-op — rebuild/ship the gateway image first).
2. Delete `gateway-state.ann` **and** `gateway-state.ann.keys` from the
   gateway's `/data/state/` (see the [ANN wipe warning](#what-to-back-up)).
   The ANN is a derived cache; the authoritative embedding rows in
   `gateway-state.recommend.sqlite` survive.
3. Restart the gateway. It boots with an empty index and rebuilds from
   SQLite.
4. Re-embed the library — the 512-dim CLAP vectors are useless to a
   768-dim index, so every track needs a fresh CLaMP 3 pass. The
   recommender runs in degraded mode (tag-only similarity) until the
   queue drains.

Skipping the wipe leaves a stale 512 `.ann` on disk; `AnnIndex::open()`
loads it without a dim-mismatch guard and the index goes split-brained.

## Split-host deployment (gateway + remote embedder)

This is the **a supported split-host topology**: a **CPU-only host** (
running `crates-gateway` + `crates-caddy`) hosts the gateway and dials
the embedder over the LAN, while a separate **GPU workstation** (the GPU host, with an RDNA4 GPU) runs the embedder sidecar. The embedder
image is **never shipped to the NAS** — only the gateway + caddy images
go there; the GPU box builds and runs the embedder locally. The embedder
is a stateless HTTP service, so this is a configuration concern, not an
architectural one — but the default `docker-compose.yml` assumes
co-located containers, so two new compose files exist for the split
layout:

| File | Purpose |
|---|---|
| `docker-compose.gateway-only.yml` | Just the gateway. Requires `EMBEDDER_URL` pointing at the remote embedder. On a CPU-only gateway host, also set `RECOMMEND_EMBEDDING_DIM=768` to match the CLaMP 3 embedder. |
| `docker-compose.embedder-only.yml` | Just the embedder, with its port published on the host network. Stacks with `docker-compose.clamp3-rocm.yml` (production), or `docker-compose.clamp3.yml` / `docker-compose.clap.yml` / `docker-compose.clap-rocm.yml` for the other backends. |

The gateway dials the embedder over the LAN; the embedder doesn't
need a route back. Audio bytes (~3–10 MB per track) ride the request,
so an ingest run is bandwidth-cheap compared to Navidrome serving
those same bytes to the gateway in the first place.

### Sharing a bearer token

The embedder accepts unauthenticated requests by default. On a
trusted LAN with no untrusted devices that's defensible (same threat
model as Navidrome). Split-host adds at least one network hop where
the embedder is reachable from anything that can route to it, so a
shared bearer token is the recommended defense:

```bash
# On either host — pick one, share with the other via your usual
# secrets path (password manager, etc).
openssl rand -hex 32
# e.g. 6a9c… (32 bytes hex; 64 chars)
```

Set `EMBEDDER_BEARER_TOKEN=<same value>` in the `.env` on **both**
hosts. The gateway attaches `Authorization: Bearer <token>` to every
outgoing call; the embedder rejects requests without the matching
token with 401. `/healthz` stays open on the embedder so boot probes
don't need the secret.

When unset on both sides, the embedder runs un-authenticated — fine
for `localhost` co-located deploys, not recommended otherwise.

### Bringing up the GPU box (embedder)

```bash
# On the GPU box — clone the repo (the embedder image builds from
# this checkout's Dockerfile + services/embedder/).
git clone https://github.com/<you>/crates-music
cd crates-music

cp docker/.env.example .env
$EDITOR .env
# Set:
#   EMBEDDER_BEARER_TOKEN=<the shared secret>
#   EMBEDDER_PORT=9000             # default, change if port-conflict
#   CLAMP3_CHECKPOINT=/models/clamp3_saas.pth   # if running CLaMP 3
#   MERT_FOLDER=/models/MERT-v1-95M             # CLaMP 3 frontend
#   EMBEDDER_BACKEND=clamp3                      # CLaMP 3 selector
#   CLAP_CHECKPOINT_PATH=/path/to/clap.pt        # only if running CLAP

# Bring it up — pick one of:
#
# (a) CLaMP 3 ROCm GPU inference (production — this is the live shape):
docker compose -f docker-compose.embedder-only.yml \
               -f docker-compose.clamp3-rocm.yml up --build
#
# (b) CLaMP 3 CPU inference (hermetic, no GPU):
docker compose -f docker-compose.embedder-only.yml \
               -f docker-compose.clamp3.yml up --build
#
# (c) stub backend, no GPU, deterministic vectors (dev / smoke):
docker compose -f docker-compose.embedder-only.yml up --build
#
# (d) legacy CLAP CPU / ROCm (512-dim alternative):
docker compose -f docker-compose.embedder-only.yml \
               -f docker-compose.clap.yml up --build
docker compose -f docker-compose.embedder-only.yml \
               -f docker-compose.clap-rocm.yml up --build

# Confirm from the gateway box that the embedder is reachable:
curl http://gpu-box.lan:9000/healthz
# CLaMP 3 (production):
# {"status":"ok","model_loaded":true,"model_version":"weights_clamp3_saas_h_size_768_...","dim":768,"device":"cuda"}
```

`/healthz` works without a bearer token — that's intentional. The
inference endpoints (`/embed/audio`, `/embed/text`, `/reduce`)
require one when configured.

### Bringing up the gateway box (no local embedder)

```bash
cd crates-music
cp docker/.env.example .env
$EDITOR .env
# Set:
#   NAVIDROME_URL=http://nav.lan:4533
#   NAVIDROME_USERNAME=alice
#   NAVIDROME_PASSWORD=wonderland
#   EMBEDDER_URL=http://gpu-box.lan:9000       # the GPU host
#   EMBEDDER_BEARER_TOKEN=<the same secret as the GPU box>
#   RECOMMEND_EMBEDDING_DIM=768                 # must match the CLaMP 3 embedder

docker compose -f docker-compose.gateway-only.yml up --build
```

This box is CPU-only — it never runs the embedder, so no GPU, ROCm
wheels, or device passthrough are needed here. The gateway logs
`embedder: ready model=… dim=768` on first probe (CLaMP 3; `dim=512` if
you're still on CLAP).
If the embedder is unreachable at boot, the gateway logs a warning
and starts in degraded mode (recommendation endpoints fall back to
tag-only similarity); restart the gateway after fixing connectivity.

### Limitations of the split-host layout

- **No `/reduce` (UMAP projection).** The reducer opens the
  gateway's `gateway-state.recommend.sqlite` directly — it needs the
  file on the same host. In split-host mode that file lives on the
  gateway box, not the embedder box. Audio + text embedding are
  unaffected (bytes ride the request). The 2-D projection feature on
  the diagnostics page just shows "no projection yet" until you do
  one of: run the gateway and embedder on the same host, mount the
  recommend SQLite over a network filesystem (NFS / SMB), or move
  the reducer to the gateway side. None of those are wired today.
- **No automatic failover.** If the GPU box goes down, ingest stalls
  until it comes back. Existing embeddings keep working; the
  recommender doesn't need the embedder to serve `/v1/recommend/next`
  for already-embedded tracks.
- **No TLS on the embedder hop by default.** http:// over the LAN is
  the documented path. If you need TLS, front the embedder with
  Caddy/Traefik on the GPU box and point `EMBEDDER_URL` at the
  https:// fronting URL.

## Known limitations (Phase A + B)

- **No multi-arch builds.** x86-64 only; ARM hosts (Pi 5, Apple
  Silicon) will fail to pull any of the embedder images. The CLAP and
  CLaMP 3 variants are especially x86-64-pinned because the PyTorch
  CPU+ROCm wheels are.
- **No CI pipeline.** Images are built locally. GitHub Actions matrix
  build + GHCR push is Phase D.
- **No automatic cert rotation.** The self-signed cert expires after
  825 days; replace by stopping the stack, deleting `certs/*.pem` from
  the volume, and starting again.
